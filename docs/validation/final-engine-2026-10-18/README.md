# 핵심 엔진 최종 안정화 증거

이 기록은 PHASE 3.9의 누적 USD2 승인 안에서 수행한 실제 OpenAI 추출·의미 분석과 무료 원문/응답 재생을 구분한다. 실제 고객 PDF, API 키, 원문 전문, 최초 모델 raw 응답은 공개하지 않는다. Set2 원본과 물리적으로 바꾼 오류본은 비공개 평가 입력이다. 나머지는 합성 자료이며 실제 고객 문서 일반화 검증으로 표현하지 않는다.

## 실제 원인과 변경

- Native 행 범위: 분리된 헤더와 닫힌 합계 영역이 가상의 추가 품목/컨테이너 행으로 계산되어 전체범위가 미입증되고 HS 검사가 보류됐다. 실제 헤더·합계·값 행을 구분하고, 진짜 추가 행 누락은 계속 불완전으로 남긴다.
- 요약과 품목 소속: AI의 문서 요약 후보가 미확인이어도 별도로 독립 검증된 완전 범위의 단일 실제 품목이 있었다. 비교용 참조는 그 품목으로 선택하되 잘못된 요약 후보·최초값·현재값·진단은 그대로 보존한다. 사용자 수정/명시적 비움, 복수·불완전 품목, 다른 문서/근거 없는/OCR 값은 이 선택으로 검증 성공 처리하지 않는다.
- 의미 대응: 서로 다른 상품이라는 부정 의견까지 양성 매칭처럼 세어 정상 다품목을 모호하다고 판단했다. 양성 대응과 부정 교차 대응을 구분하고, 모든 문서쌍의 전체 원문 행과 유일한 일대일 대응을 확인한다. 같은 pair의 상충 중복 의견은 여전히 보류한다.
- 행별 HS: 전체 HS 집합이 같아도 품목별 코드가 서로 바뀌면 오류다. 같은 native 소속 행의 검증된 6자리끼리 비교한다. AI 언어 의견만으로 HS 숫자를 생성·복구하지 않는다.
- 조치와 정보: 성공한 AI 언어 대응은 잠정 정보이며 확정 일치가 아니다. 같은 원인의 정보성 설명을 통합하고, 원본 checks/AI decisions/이전 이유와 독립 수치 오류를 보존한다. 화면/보고서는 상태 문구와 미사용 후보 안내만 변경했고 디자인은 바꾸지 않았다.

## 실제 실패도 보존

최초 a57 Set2 실제 분석은 핵심 일치11·확정오탐0·조치4였다. 첫 보강7087의 무료 재생은 조치0이었지만 새 실제 응답은 중복 요약 후보로 조치1이 남았다. a4의 새 실제 응답도 다른 헤더를 인용한 요약 후보 때문에 조치1이 남아 유료 평가를 중단했다. 해당 실제 응답을 후속 코드로 무료 재생했을 때 조치0·핵심일치12이며 원본 미확인12는 그대로 보존됐다. 이는 새 AI 재추출 성공과 구분한다.

7087 다품목 실제 응답의 정상 양성4/정상 부정4가 모두 모호한 대응으로 집계된 것을 고쳤다. 무료 재생에서 관련 보류10→0. 과거 합성 신고서의 실제 Exporter 누락1건은 여전히 남겨야 한다. 이후 평가 입력에는 Exporter 라벨을 실제로 넣었다. 자료를 고친 효과를 엔진 정확도 개선으로 계산하지 않는다.

## 평가와 재현

최종 summary.json은 새 동일 Production SHA의 첫 추출과 별도 의미 요청 결과다. package는 실제 업로드 UI 전체 흐름으로, 다른 Set2 오류는 변경하지 않은 동일SHA 부모 응답2개를 재사용하고 변경 PDF1개만 새 추출한다. oracle/정답은 provider 요청에 보내지 않는다. 역할별 실제 PDF 변경 증명은 입력 해시·변경 여부만 공개한다.

ReportLab의 새 2페이지·역순열·가로형 신고/세로 운송 양식은 두 시나리오의 한 새 레이아웃 계열이다. 이를 여섯 독립 고객 양식으로 계산하지 않는다. 기존 PHASE39 개발 자료와 구별한다.

## 비용 보존

모든 단계 실패/재검증도 같은 ledger에 포함한다. 진행 중 원격 체크포인트의 예약이 사용량 확인 후 다시 복원된 건은 실제4개 응답의 usage 증거로만 대조했다. 문서·요청·이전 비용을 초기화하지 않았으며 미확인 타임아웃을 무료 처리하지 않았다. 이후 체크포인트는 실행 잠금이 없는 경계에서 저장한다. 가격은 코드의 공개 가격표·provider usage 기반 추정이며 청구서 검증은 아니다.

## 한계

AI의 최초 추가/요약 후보가 항상 정확한 것은 아니다. 미검증 후보는 확정 근거가 아니며 원본 진단을 보존한다. 성공 언어 의견은 잠정 정보다. 불완전/중복/부분선적 범위는 자동 확정하지 않는다. 과거 251 최초 응답은 없어 그 생성 원인을 재구성하지 못했다. 이번 최초 분석의 실제 값과 원문 검증/복구 성과를 별도로 기록한다.

Vercel 관리 API Ready는 직접 조회하지 못한다. GitHub Vercel 성공 상태, Production Git deployment success, 공식사이트 exact SHA 응답을 각각 확인한다. 최종 source SHA와 evidence branch의 기록 SHA는 서로 다르다.
